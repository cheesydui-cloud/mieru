# v0.5.8 面板一键迁移（完整导出 + 覆盖导入）

## 目标

在**设置页**提供真正可用的换机能力：

1. **一键导出完整迁移包**（含密钥，可恢复节点/用户/隧道）
2. **一键导入并覆盖**到新面板（保留 ID / agent_token / 代理密码 / 订阅 token）
3. 导入后自动 **重建配置**，节点凭原 token 心跳即可（若面板 URL 变了，只需改节点 `PANEL_URL`）

现有「下载备份」**保留不动**（安全快照、无密钥，仅作日常参考）。

---

## 为何不能只靠现有备份

| 现有 `GET /api/admin/backup` | 完整迁移需要 |
|---|---|
| 无 `agent_token` | 必须有，否则节点全掉线 |
| 无用户 `proxy_password` | 必须有，否则代理连不上 |
| 无 `backbone_pass` / CF token | 必须有，否则多跳/CF 断 |
| 无管理员密码 | 应恢复，换机后还能原密码登录 |
| 无导入接口 | 要做 `POST` 覆盖导入 |

## 后端设计

### 新 API

```
GET  /api/admin/migration/export
POST /api/admin/migration/import
```

均需管理员鉴权。

### 导出格式 `mieru-panel-migration` v1

```json
{
  "format": "mieru-panel-migration",
  "format_version": 1,
  "exported_at": "...",
  "panel_version": "v0.5.8",
  "secrets_included": true,
  "settings": { "panel_url": "...", "backbone_pass": "...", "cf_api_token": "...", ...全部 key },
  "admins": [{ "username": "admin", "password_hash": "..." }],
  "nodes": [{ "id", "agent_token", "name", "role", "ports", "hostname", ...全字段 }],
  "routes": [{ "id", "name", "hops_json", ... }],
  "users": [{
    "id", "username", "proxy_password", "sub_token",
    "status", "expire_at", "traffic_*", "route_id",
    "entry_*", "note", "display_multiplier", "speed_limit_bps", ...
  }],
  "announcements": [ ... ],
  "traffic_hourly": [ ... ],
  "note": "含密钥；仅用于面板搬迁；勿外传"
}
```

**故意不导出**：`node_desired_config`（导入后 `RebuildAll` 重算，避免旧配置与新版本不兼容）。

**不导出 JWT**：JWT 在 `/etc/mieru-panel.env`，只影响浏览器会话；agent 用 token。导入说明里写：新机可重新生成 JWT，旧登录态失效正常。

### 导入语义（唯一模式：覆盖）

为「换机」场景做死 **replace**，不做半吊子 merge，避免 ID 冲突用坏：

1. 校验 `format == mieru-panel-migration` 且 `format_version == 1`
2. 必须 `secrets_included` 且 nodes 有 token、users 有 proxy_password（缺则 400）
3. **单事务**：
   - 清空：`traffic_hourly` → `users` → `routes` → `nodes` → `announcements` → `node_desired_config` →（可选）`settings` 全量替换
   - 写入 settings / admins / nodes（**保留原 id + agent_token**）/ routes（**原 id**）/ users（**原 id + proxy_password + sub_token**）/ announcements / traffic_hourly
4. 事务提交后 `RebuildAll()`
5. 返回摘要：`{ ok, nodes, routes, users, announcements, traffic_rows, rebuild_ok, warnings[] }`
6. 审计：`export_migration` / `import_migration`

### Store 扩展（`internal/store`）

新增集中方法，避免 handler 里堆 SQL：

- `ExportMigration() (*MigrationSnapshot, error)` — 读全表含密钥
- `ImportMigration(snap *MigrationSnapshot) error` — 事务覆盖
- 底层需要（当前 Create 会改 ID 的要补）：
  - `insertNodeExact`（含 agent_token）
  - `insertRouteWithID`
  - `insertUserWithID`（用明文 proxy_password 重算 bcrypt + 写 plain）
  - `replaceAdmins`（写 password_hash）
  - `listAllSettings` / 全量 settings 替换
  - `listTrafficHourly` / bulk insert
  - `ListAdmins` 或内部读 admins

`UpdateNode` 目前**不更新** `agent_token`，导入走专用 insert，不碰半更新路径。

### API handler（`internal/api/server.go`）

- `exportMigration`：`Content-Disposition: mieru-migration-<ts>.json`
- `importMigration`：
  - body = 迁移 JSON
  - 可选二次保险：`{"confirm":"IMPORT"}` 包一层，或请求头 `X-Confirm-Import: 1`（前端双 confirm + 该头）
  - 体积：JSON 解析即可（面板数据通常不大）；过大可 413

### 测试

- `internal/store/migration_test.go`：建库 → 造 node/user/route/setting → Export → 新库 Import → 比对 id/token/password/sub_token/settings → 再 Export 一致
- 缺 token / 错 format 应失败且不污染库

## 前端（`web/src/views/Settings.vue`）

在现有 **「备份导出」** 与 **「管理员」** 之间新增面板：

### 完整迁移（含密钥）— 危险区样式

`border-color: var(--danger)`

**导出**
- 按钮：`导出完整迁移包`（`btn-danger`）
- `confirm` 警告含密钥
- 与现备份一样：`fetch` + Bearer + Blob 下载（**不用** `api()`，避免 blob 被当 JSON 解析）
- 文件名：`mieru-migration-YYYY-mm-dd-HHMMSS.json`

**导入**
- `<input type="file" accept=".json,application/json">`
- 本地 `FileReader` 解析后展示摘要：版本、时间、节点/隧道/用户数
- 按钮：`导入并覆盖本机数据`（`btn-danger`，未选文件禁用）
- **两次** `confirm`（与现有删用户风格一致）
- `POST /api/admin/migration/import`，header `X-Confirm-Import: 1`
- 成功 flash + 提示：若换了 IP/域名，请改各节点 `/etc/mieru-agent.env` 的 `PANEL_URL`，并更新设置里「面板公网地址」
- 若管理员密码被覆盖：提示用**旧面板密码**重新登录

保留原「下载备份」文案，标明「不含密钥，不能用于换机」。

## 换机标准流程（写进 UI 帮助文案）

**旧机**
1. 设置 → 导出完整迁移包（离线保存）
2. （建议）`systemctl stop mieru-panel`

**新机**
1. 安装面板二进制（同版本或更新）
2. 登录新面板 → 完整迁移 → 选择文件 → 导入并覆盖
3. 设置「面板公网地址」为新 URL
4. 各节点：`PANEL_URL=新地址` 后 `systemctl restart mieru-agent`（token 不用改）
5. 面板点「重建配置」确认（导入已自动 rebuild，二次可选）

## 明确不做

- 不做 merge 半合并（易脏）
- 不做迁移包加密口令（首版靠权限 + 二次确认；需要可后续加）
- 不自动改远程 agent 的 `PANEL_URL`（无 SSH 通道）
- 不把 JWT 写进 JSON（避免和 env 双源；会话失效可接受）

## 验收标准

1. 旧面板导出 → 新空面板导入 → 用户/隧道/节点 ID 不变  
2. 节点用原 `/etc/mieru-agent.env` 只改 URL 能上线  
3. 用户代理密码、订阅链接不变  
4. 管理员原密码可登录  
5. 错误包/缺密钥导入失败且数据库不被半截写入  
6. 原「下载备份」行为不变
